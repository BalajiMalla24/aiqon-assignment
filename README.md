# Shipment ETA and Delay Propagation

This project predicts a shipment's final arrival delay and the likelihood that it will arrive more than 24 hours late. It uses a reproducible synthetic dataset to demonstrate stage-level delay propagation, ETA prediction, and interpretable model outputs.

## Problem Definition

The forecast is made after customs clearance at the destination port. Delay is the difference between actual and scheduled final arrival, in hours. Predicted ETA is calculated as scheduled final arrival plus predicted delay. A shipment is classified as late when its delay exceeds 24 hours.

## Approach

The simulator creates 240 shipment journeys across four routes. Departure, sailing, port waiting, processing, and customs delays contribute to the observed delay at the forecast checkpoint. Congestion, weather exposure, and downstream variation influence the remaining delay.

The model uses stage delays, route and calendar features, and two interactions: congestion multiplied by port processing time, and weather severity multiplied by route exposure. Ridge regression predicts delay in hours. Logistic regression estimates the probability of exceeding the 24-hour threshold. Both models use standardized features. For each example, signed regression contributions show which features push the predicted delay higher or lower; they explain the model output, not causality.

Evaluation uses a deterministic 75/25 random split. Regression is measured with mean absolute error (MAE) and compared with a training-mean baseline. Late classification is measured with accuracy, precision, recall, and F1, and compared with a majority-class baseline.

## Requirements and Run

Python 3.10 or later is required. From the project root, run:

```powershell
python -m pip install -r requirements.txt
python eta_model.py
python -m unittest discover -s tests -v
python build_report.py
```

`eta_model.py` writes `data/shipments.csv`, prints held-out metrics, and shows one explained prediction. The tests check data reproducibility, timestamp-based delay calculation, and model outputs. `build_report.py` creates `report.pdf` and recalculates its metrics from the dataset. The prediction pipeline uses only the Python standard library; ReportLab is used to generate the PDF.

To regenerate the data with a different size or seed:

```powershell
python eta_model.py --records 300 --seed 10 --output data/shipments.csv
python build_report.py
```

## Default Results

With 240 records and the default seed, the test set contains 60 shipments. MAE is approximately 2.08 hours, compared with 10.87 hours for the training-mean baseline. Late-classification F1 is approximately 0.94; accuracy is approximately 0.93, compared with 0.53 for the majority-class baseline. These figures measure performance on data generated by this simulator only.

## Assumptions and Limitations

The records are synthetic, not historical carrier or port data. Congestion and weather are assumed to be available at the forecast checkpoint; a real system must verify that each input was available at prediction time. The random split evaluates records drawn from the same simulated routes and time range, so it does not demonstrate performance on future periods or unseen routes. The late probabilities are not calibrated on real outcomes.

A real deployment would require timestamped shipment history, forward-in-time validation, checks for missing or late stage data, performance analysis by route, and probability calibration. The current results demonstrate a reproducible approach, not production accuracy.
